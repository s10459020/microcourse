# 教學元素工具箱（非封閉清單）

元素是**單元內可選擇的教學手段**，不是單元分類或硬性欄位。不應要求每單元都同時使用下列元素；沒有合適元素時，由 AI 設計更適當的方法並驗證。

| 元素 | 適用情境 | 典型互動／最低要求 |
|---|---|---|
| Concept Map / Structure | 名詞關係、HTML DOM、系統分層 | 點選節點顯示關聯；線條與文字要一致 |
| Guided Visual / Step | 因果鏈、機制、操作流程 | 上一步/下一步，逐步標出發生的事 |
| Comparison | 兩種寫法或條件差異 | 並排或切換，同時標明比較基準 |
| Interactive Demo | 點選狀態或調整參數能立即感知差異 | 控制項與呈現結果真正連動 |
| Try Code | 程式語法、除錯、實作訓練 | 可修改、可預覽/執行、可重設；檢查規則不只比對單一字串 |
| CSS Showcase | CSS 版面、樣式、動態效果 | 調整屬性並顯示前後效果；必要時顯示相應 CSS |
| Source Caveat / 技術提醒 | 來源有簡化、歧義、疑似錯誤或需修正的例子 | 與相關概念並列「原講法」和精準澄清，不藏在全域說明或來源報告中 |
| Quick Check | 概念判斷、預測結果 | 答錯也有解釋與修正機會 |
| Scenario / Decision | 跨步驟判斷、設計選擇 | 讓學習者作決定，顯示理由和後果 |

## 選用判斷

- 先問：「這個單元需要讓學習者**理解什麼**？能否用視覺關係、變化或操作把它說清楚？」優先選能直接展示知識結構或因果的視覺元件，不從既有元件倒推教學內容。
- 若只需理解狀態差異，優先採用可見的比較或 Demo，而非要求閱讀大段程式碼；程式碼只是輔助資料，不等於視覺化講解。
- 若目標含**實際編寫或除錯**，應保留可練習該技能的 Try Code 或等效操作；若要理解背後關係，先提供結構標示、流程或對照，而不是加更多可編輯程式碼。
- 領域不相符時不使用：CSS Showcase 不應套在歷史課上；其他領域可以設計時間軸、模擬、地圖或自有元素。
- 新增元素不需要先修訂這份文件；若多次重複使用且可明確定義適用時機，再考慮納入共用工具箱。

## 技術與驗收提醒

- 元件可以由 HTML/CSS/JS、Canvas、SVG、圖表庫或其他技術完成，沒有預設堆疊。
- 若是動態視覺，確認控制真的造成預期變化；如果只是示意圖，不冒充真實模擬。視覺元件必須解釋關係或變化，不能只有裝飾效果。
- Try Code 類執行環境必須限制權限、避免任意不可信程式碼進入宿主頁面的權限邊界。
- 練習檢查優先以**最終可觀察的行為、結果或語意**判定；須留意其他條件可能抵銷中間步驟，不能僅憑正確片段存在就宣稱整體正確。若只能用近似或局部規則，須說明可驗證範圍，避免誤判成功或錯誤拒絕合理的正確解答。
