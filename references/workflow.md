# 來源辨識與教材轉換流程

此文件規定 AI 在產生網站前要完成的思考與查核工作，並非強制的輸出檔案格式。

## 1. 盤點來源

對每份輸入建立內部或可呈現的簡明紀錄：來源識別、型態、可讀內容、主要主題、可追溯位置（如投影片頁碼、逐字稿段落或既有時間戳）及缺漏。可接受：**只有教材檔案、只有影片逐字稿、或兩者同時輸入**；也可各有多份。

- PPT 等教材檔案：PPT 不只讀標題與文字，也注意圖表、講者備註、程式範例及練習題。無法讀取的部分要明確標示；其他已提供的文件依其可讀內容處理，暫不規劃個別前處理器。
- 影片逐字稿：以**已取得的文字**為輸入，辨識概念、口頭案例、提示與問答。保留有用的段落/時間戳，若沒有時間戳也能繼續。**不執行影片轉錄、音訊辨識、抽影格或聲畫同步**。
- 若只有原始影片、沒有可讀的逐字稿：說明缺少文字來源，請使用者提供逐字稿。若逐字稿出現「看畫面」「這裡的按鈕」等未附具體資訊的指涉，先標記缺漏；可搭配已提供的 PPT 對應，但不能猜測未見畫面。
- 引用來源位置以支援追查即可；不能因來源有 55 頁就建立 55 單元。

## 2. 辨識多來源的關係

先在**主題/知識點層級**比對，再彙整為來源層級的關係；一份授課逐字稿可能只對應一部分 PPT。只有單一來源時跳過跨來源比對，但仍要整理該來源內部的知識關係。

| 關係 | 判定線索 | 處置 |
|---|---|---|
| 重複 | 描述相同概念、例子與目標 | 消除重複教學，保留多個來源指向 |
| 互補 | PPT 摘要 + 影片逐字稿中的口頭步驟或案例 | 形成更完整解釋，註明兩者貢獻 |
| 部分重疊 | 一些知識點相同，另有獨特內容 | 共享觀念只教一次，新增內容另行編排 |
| 矛盾 | 同一命題或操作給出相互衝突的結論 | 標註衝突並查證；無法確認則呈現不確定，不暗中選邊 |
| 無關 | 目標、術語、先備依賴皆不同 | 規劃為不同課程或路線，不假造關聯 |
| 不明 | 資料不完整，無法確認相符性 | 標示待確認；若會改變主要架構則詢問 |

辨識內容同時要區分「同一領域但不同主題」與「有實際先備依賴」：同領域不代表必須併成一個單元。

## 3. 建立知識地圖

由來源整理：

- 概念：可以獨立敘述的知識命題及其可理解前提。
- 關係：先備、包含、並列、比較、因果、例外等。
- 證據：對應來源位置；保留原案例，能沿用時優先沿用。
- 風險：疑似錯誤、不完整、過時說法或互相衝突的描述。
- **教學角色**：逐段辨識概念講解、正確示範、刻意錯誤案例、練習題、解答及補充說明，並檢查相鄰頁面／段落及講者備註是否已提供解答或澄清。
- **預期能力與結果**：辨識來源究竟要求學習者辨認、解釋、預測、操作、製作、分析、解題、除錯、整合或驗證什麼；記錄可觀察的行為、判斷、產物或成果，尤其區分「看懂現成結果」與「自行完成任務」。

**判斷技術錯誤前先判斷教學角色**：練習題中故意設計的錯誤寫法，不等於來源在教授錯誤知識；若後續已有解答，也不能孤立抽出題目加上「來源錯誤」的技術提醒。角色不明時先檢查上下文；仍無法判定再標示不確定，不能擅自認定講師教錯。**提出糾錯或技術提醒前，還須確認來源其他位置是否已解釋相同限制**；已說明的內容可重新整理或延伸，但不可將它歸因為來源的遺漏或錯誤。

區分三種材料身分：**來源敘述**、**教學新增例子**、**查證修正**。必要時查證，不能把來源錯誤無警示地教出去；但也**不能默默抹除、改寫原來源的有問題說法**。保留可辨識的原講法，並在對應單元、原理或示例旁加上精簡的技術提醒，呈現澄清及查證依據；沒有把握時明確標註未知。來源頁碼／時間戳保留在內部對照紀錄即可，不需放進學習者介面。

## 4. 編排而非照搬

1. 先判斷來源包含幾條合理的課程/章節路線。
2. 在每條路線中按先備順序排列主題。
3. 為每個主題定義唯一的主要學習目標與相鄰單元的差異；若結合多個概念，確認「比較／整合」正是需要學會的目標，而不只是這些概念剛好出現在同一段教材。
4. 先確認單元能完整教授一個明確目標，再視需要估算「理解視覺解釋 + 操作/測試 + 回饋/修正」所需時間；5 分鐘僅供參考，較短不用補滿，較長也不單憑時間拆分。只有確實存在不同且完整的子主題時才拆開。
5. 執行來源覆蓋與**學習目標等效**檢查：重要概念、練習類型、目標能力及預期成果都要能對應到單元；未納入的內容須有原因。可改變呈現方式，但不能將來源要求的操作、創作、分析、除錯或驗證無故降為觀看、選擇答案或下載現成成果；來源若要求綜合應用，也須有學習者親自整合所學的機會。

可用簡單表格規劃，不必強迫所有 AI 產生特定的 JSON/YAML：

| 單元 | 主目標 | 與相鄰單元的區別 | 先備 | 預估時間 | 來源位置 | 教學元件 |

## 5. 教學設計、實作與驗收

### 成品入口與資源組織

- **使用入口明確**：每份成品都要有單一、清楚的**建議開始方式**（例如開啟入口頁、執行啟動指令或存取網站網址），並以極短 README 告訴使用者如何開始。這不代表所有技術都必須提供固定檔名或單一實體入口檔。
- **必要且有序**：入口與極短使用說明清楚可見，其餘執行依賴依用途分層，避免輔助檔案被誤認成入口。**僅按需建立目錄**，不規定 `pages/`、`assets/` 等名稱；不打包重複版本、暫存檔、空目錄、未引用素材、除錯輸出或開發文件，也不為追求特定檔案數而硬拆或硬合併。
- **練習與匯出隔離**：範例／練習下載的預設檔名、目錄與安裝指示不得讓學習者意外覆蓋課程入口、成品資源或其他練習作品。若來源練習確實要建立 `index.html` 等常見入口名，應在獨立的練習專案／下載區使用，清楚區分「課程本體」與「練習產物」，而不是犧牲原練習目標。
- **從入口驗收**：按照交付給使用者的方式啟動，檢查依賴載入、單元切換、示例跳轉、相對路徑與資源引用；實際下載練習產物並依指示操作一次，確認沒有撞名、覆蓋風險或缺失的引用目標。

- **由學習證據反推設計**：先決定本單元要讓學習者看懂的關係、做出的判斷或完成的成果，再選擇最能呈現其原理的視覺手段，以及必要的操作、說明與回饋；**不得為每個單元複製相同的元件順序、種類或數量**，也不為求表面變化加入不必要元件。詳見 [教學原則](teaching.md)與[元素工具箱](elements.md)。
- **整合任務不能只交付解答**：來源或目標若要求學習者綜合運用多個已學能力，須讓學習者親自完成任務的關鍵決策、步驟或產物，並有可觀察的檢查與回饋；可提供示範與參考成品，但它們不得是唯一活動。原本只有概念理解目標時，不必為了形式上「有專題」而硬加整合任務。真實操作的結果須實際驗證，不能以未說明限制的模擬冒充。
- **單欄連續學習**：學習正文從上到下依理解順序安排，桌面寬螢幕仍維持一條主要閱讀流，不把「講解區／互動區／練習區」或多個完整知識段落左右並排。局部雙物件比較、圖示內分欄或編輯器與其預覽可按功能必要短暫並排，但不能讓學習者必須左右跳讀或使內容顯得擁擠；適當限制閱讀寬度、留白與段落節奏，讓下滑自然呈現學習進展。
- **單元內一致性**：逐單元核對標題、列舉數量、步驟次序、核心主張、圖像標示、技術提醒、示例、互動狀態、練習起點、指令、判定規則、參考答案與回饋，確保描述同一情境或明確區別情境。尤其檢查「說有幾項」與實際顯示數量是否相同、「要求學習者修正的條件」是否真的存在於對應練習，以及完成狀態是否符合判定；刻意錯誤須清楚標為練習而非彼此矛盾的解說。
- 網站應能清楚辨識章節/單元、進入前後單元、展示學習內容與操作結果；必要時保存進度，但不強制建立帳號。
- 任何 Try Code 或可編輯執行環境都要有適當隔離，避免把使用者輸入當成受信任程式執行。
- **評量與完成宣稱須有證據**：先確認該目標有哪些必要成果，再區分「局部檢查通過」「最終結果已驗證」與「學習目標完成」。只檢查部分條件，不得直接宣稱整體完成；無法自動確認的條件，應說明限制並標為待驗證，或提供可實際執行的人工驗證步驟。若結果可能受到其他條件影響，應盡可能檢查**最終實際生效的狀態**，不以某個正確片段或中間步驟存在就斷言結果正確。
- 測試包含：由建議入口正常啟動、必要引用目標存在、實際導覽／跳轉正確；對代表性練習檢查**未完成、正確完成、常見錯誤、表面符合但最終結果錯誤**的行為及回饋，並考慮合理的等效正確解法；核對學習成果而不只測試參考答案能過關；**寬螢幕與手機皆維持單欄主閱讀流、無不必要左右擠壓或水平捲動**；檢查練習下載後的檔名及引用目標。
- 若沒有瀏覽器或其他必要能力，列出未做的測試，而不是虛構通過。
- 最終給學習者的 ZIP 只包含可運作的網站檔案與極短 README（如何啟動／操作）；來源追溯、覆蓋紀錄、測試報告與製作過程應留在成品外。學習者介面只呈現學習所需資訊，重要限制就地說明，避免來源頁數、檔名或轉換過程占據課程內容。

## 最小驗收問題

1. **來源**：是否讀懂所有輸入、跨來源關係及原始教學角色？刻意錯誤與已在其他地方澄清的內容，有沒有被誤當來源錯誤？
2. **單元**：是否依明確的學習目標、同質性、區別性及完整性切分，並將時長視為參考，而非湊內容的理由？
3. **能力**：來源要求的理解、操作或整合能力是否有等效學習活動？需要親自完成的關鍵步驟有沒有被示範或參考答案取代？
4. **呈現**：能視覺解釋的概念是否有真正反映原理的展示？教學流程有沒有依目標選擇、而非固定模板？正文是否在寬窄螢幕均保持單欄縱向閱讀？
5. **一致**：標題、列舉數量、解說、情境、步驟、圖解、練習、答案及回饋是否相符？
6. **評量**：是否測試未完成、正確、典型錯誤及表面正確但最終結果錯誤的情況，並允許合理等效解答？完成狀態是否只宣稱實際有證據支持的部分？
7. **成品**：入口、依賴、導覽、互動、練習匯出是否真能使用？目錄、檔名與 README 是否精簡、不混淆也不會覆蓋其他成果？無法完成的測試是否明確揭露？
